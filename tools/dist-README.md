# 弧光歌词 · ARCLYRIC

**把歌词戴在腕上。** 小米手环 9 Pro（Vela OS）歌词播放器 + 手机伴侣。

| 包 | 说明 |
| --- | --- |
| `Arclyric-1.0.3-release.apk` | 手机端，日常使用 |
| `Arclyric-1.0.3-release.rpk` | 手环端，日常使用 |
| `Arclyric-1.0.3-debug.apk` | 手机端调试包（同证书，仅日志更多） |
| `Arclyric-1.0.3-debug.rpk` | 手环端调试包 |

APK 与 RPK 同包名 `com.vela.lyricplayer`、同证书，可互相覆盖升级。

## 1.0.3 更新

- 歌词本翻页重做：不再「一次滑一行、每 180ms 才响应」，改成手指划过 0.8 行就滚一行，跟着手指走；抬手时剩余位移补一行当惯性。列表和阅读页都改了。
- 列表 / 阅读页窗口行数恒定（末尾补空行），滚动时框架只改文字，不重建节点树，几百首也不掉帧。
- 去掉 `@swipe` 与时间节流，避免抬手瞬间跳一大段造成的卡顿感。
- 修空行占位被点开的问题。

## 1.0.2 更新

- 修手机切歌时手环停在上一首 / 结尾秒数：手机每 2 秒兜底重发状态，切歌后再补发两次；手环播到结尾或 20 秒没收到状态会主动要一次。
- 修发包风暴：两边都给握手加冷却（手环 20 秒、手机 8 秒），重复的 hello 不再触发整首歌词重发；词库请求不再每次都清零节流。
- 播放页新增音量控制、进度条可拖动；删除 ±10 秒按钮。

- 歌词本改为窗口式上下滑动 + 跟随播放自动滚动。
- 手机端：歌词库批量管理、日志可上滑翻看、推送排队发送。

## 安装

1. 手机装 APK，打开后授予「通知使用权」。
2. App 会自动开始同步（日志出现「已自动启动同步服务」）。
3. 手环装 RPK，桌面出现「弧光歌词」。
4. 手机上放歌，手环自动显示歌名、进度和当前歌词。

## 手机端界面

- 顶部渐变主视觉：应用名、ARCLYRIC 标语、版本号。
- 状态区：连接指示灯 + 「同步中 / 等待授权 / 未启动」，以及通知使用权、同步服务两行实时状态。
- **正在播放**：直接显示手机当前歌曲与歌手，每 2 秒刷新；下面一枚状态胶囊显示歌词进度（本地词库 / 在线匹配中 / 匹配成功 / 未匹配到）。
- 主按钮随状态切换：未运行时是「启动同步」，运行中变成「停止同步」。
- **歌词库 / 导入 LRC / 重发歌词** 三个并排入口。
- 日志区独立卡片，可上滑翻看历史（翻看时不会被新日志拽回底部），清空 / 复制 / 分享集成在标题行。

### 歌词库

从主界面点「歌词库 · 管理 / 导入」进入。页面分两个标签：

**手环词库（默认）** —— 手环端歌词本的真实镜像，列表就是手环里存着的那几首：

- 显示**歌名、歌手、行数**；点任意一条预览全文（手机里没有这首歌的缓存时会说明原因）。
- **删除** —— 同时从手环歌词本和手机缓存里删掉。
- **发送** —— 手机缓存里有同名 `.lrc` 时才出现，用来补推。
- **批量管理** —— 多选后一次性删除或推送；推送由同步服务排队，一首发完再发下一首。
- 右上「刷新」重新向手环要一份列表。

**手机缓存** —— 手机本地保存的歌词，也就是推送用的源：

- 列表显示**歌名、歌手、行数**，点任意一条全屏预览全文。
- **发送** —— 立即把这一首推到手环（不必等手机正在放这首歌）。
- **删除** —— 二次确认后从手机缓存移除，手环上的那份不受影响。
- **导入 LRC 文件** —— 系统文件选择器，可多选。
- **批量管理** —— 多选删除（只删手机缓存）或多选推送。
- **从网易云歌单导入** —— 粘贴歌单链接、App 分享文案或纯歌单 ID，自动批量抓词：
  - 最多一次导入 60 首，已在词库里的自动跳过；
  - 逐曲先取网易云带时间轴的歌词，失败再回退到 QQ 音乐 / LRCLIB 按「歌名 + 歌手 + 时长」匹配；
  - 进度实时显示 `[3/60] 歌名 · 新增 2 · 跳过 1 · 失败 0`。

## 手环界面

- **主页** —— 「播放器 / 歌词本 / 设置」三个入口。
- **播放器** —— 顶栏状态灯 + 词本 / 设置两个图标；左上角小字歌名（亮色）与歌手（灰蓝色），右侧常驻「加入歌词本」圆形图标；中间是歌词窗；下面是音量 −/＋ 与百分比、可整条拖动的进度条、上一首 / 播放 / 下一首。
- **加入歌词本** —— 点一下就把这首歌存进手环歌词本（不再每首都自动保存）。
- **音量** —— −/＋ 每次 10%，手机端换算成系统音乐音量；手机会把当前音量回传，数值以手机为准。
- **进度条** —— 按住即预览时间，松手才真正 seek，拖动时不会被每秒刷新拽回去。
- **歌词区可上下滑**：上滑往后看、下滑往前看，轻滑一句、快滑多句；停手 6 秒自动回到当前句，轻触回到当前句。
- 轻触歌名或歌词区 → **全屏歌词**（同步滚动、可上下滑浏览、点句跳转、偏移微调）。
- **歌词本** —— 列表 6 行窗口、阅读 10 行窗口，都是上下滑动浏览；阅读页跟随播放句自动滚动、当前句高亮，手动滑动后暂停跟随，点「回到当前」恢复。
- 全部按钮都用图标，不占文字位置。

除歌词浏览外，页面固定一屏，不滚动。

## 歌词

歌词来自手机，全程自动，不需要手动导入：

1. 手机端读取播放器的 MediaSession（歌名 / 歌手 / 时长）。
2. 先在本地词库找同名 `.lrc`；没有就自动在线匹配：
   - 中文曲：**自家接口服务 `api.lanhu199.top`（网易云聚合）** → QQ 音乐 → LRCLIB；
   - 其它曲：LRCLIB → QQ 音乐 → `api.lanhu199.top`；
   - 每个来源都按「标题 + 歌手 + 时长」打分，低于阈值直接丢弃，宁缺毋滥。
3. 命中后缓存进本地词库（`内部存储/files/lyrics/*.lrc`），分包推给手环。
4. 手环存进自己的歌词本，下次同曲离线也能看。

匹配不到（纯音乐、冷门曲）时手环照常显示歌名与进度，不会卡住；也可以在播放器上点「添加歌词」图标让手机重试一次。

## 排错

手机日志里会看到：

```
本地无《歌名》，正在在线匹配歌词
开始发送在线 歌词：歌名 · 1234 字 / 13 包
歌词分片已全部送达（13 包）
手环已收到歌词（1234 字）
```

歌词传输是**发一包等一包**：单包 100 字，手环收到就回 `ack`，手机收到回执再发下一包；回执 1.5 秒没到就继续发下一包，不会因为回执丢失把整首歌词丢掉。全部发完日志会打印 `歌词分片已全部送达（N 包）`，若手环一条回执都没回则打印 `歌词已发送（N 包，手环未回执）`。

这么做的原因：手环的通信缓冲很小，一次灌几十条消息会把穿戴服务冲垮，表现为掉歌词甚至整机重启。

手环端会把启动过程通过设备通信回传到手机日志：

```
[启动] app · BOOT arclyric/1.0.2 脚本已加载
[日志] page:player · onInit
[日志] init · store.load 完成 mock=false
```

手环控制手机时，手机日志出现 `手环控制：toggle` / `next` / `prev`。
